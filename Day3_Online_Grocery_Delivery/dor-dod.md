# Definition of Ready (DoR) and Definition of Done (DoD)

## Definition of Ready – checklist

A backlog story is Ready for Sprint Planning when:

- [ ] The story is written in clear As a / I want / so that format.
- [ ] The user or business value is understood.
- [ ] Acceptance criteria are written and testable.
- [ ] The story is small enough to complete within a Sprint.
- [ ] Dependencies and important assumptions are identified.
- [ ] The team has discussed the story and can estimate it.
- [ ] Required designs, sample data or business rules are available, where needed.

## Definition of Done – checklist

A story is Done when:

- [ ] The agreed functionality is implemented.
- [ ] The code is reviewed by another team member.
- [ ] Unit tests and relevant functional tests pass.
- [ ] Acceptance criteria, including negative cases, are verified.
- [ ] No known critical or high-severity defect remains open.
- [ ] The change is integrated into the shared build without breaking existing functionality.
- [ ] Relevant user or technical documentation is updated.

## How the team uses these definitions

The Definition of Ready helps the team avoid starting unclear or oversized work. The Definition of Done gives everyone a shared quality standard for completed work. A story is not marked Done merely because coding has finished; it must satisfy the agreed checks.
